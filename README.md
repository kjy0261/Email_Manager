# 메일 캘린더 위젯

**다음(Daum)·네이버·Gmail**(그 밖의 IMAP 메일도 가능) 메일을 주기적으로 확인해서, **업무 메일**이 오면 본문에서 날짜·시간을 찾아
캘린더 일정 후보로 보여주는 윈도우 바탕화면 위젯입니다. Electron 기반이고,
업무 메일 판별과 일정 추출은 AI 없이 **규칙**으로 동작합니다(외부 API 비용 없음).

## 실행 방법

```bash
npm install
npm start
```

처음 실행하면 **설정** 탭이 열립니다. 메일 계정은 여러 개를 함께 등록할 수 있고
(`+ 계정 추가`), 모든 계정을 동시에 확인합니다. 한 계정이 실패해도 나머지는 계속 동작합니다.

| 메일 | 아이디 | 미리 할 일 |
| --- | --- | --- |
| 다음 | `myid` 또는 `myid@daum.net` | 다음 메일 → 환경설정 → IMAP/POP3에서 **IMAP 사용** 켜기. 카카오 2단계 인증을 쓰면 **앱 비밀번호** 사용 |
| 네이버 | `myid` | 네이버 메일 → 환경설정 → POP3/IMAP 설정에서 **IMAP/SMTP 사용: 사용함**. 2단계 인증을 쓰면 **애플리케이션 비밀번호** 사용 |
| Gmail | `me@gmail.com` | Google 계정 → 보안에서 **2단계 인증**을 켜고 **앱 비밀번호**(16자리) 생성. 일반 비밀번호로는 로그인 불가 (공백은 자동 제거) |
| 기타 | 해당 서비스 계정 | IMAP 서버 주소와 포트(보통 993) 직접 입력 |

계정을 넣고 "연결 테스트"로 확인한 뒤 **회사 도메인**(예: `mycompany.co.kr`)을 넣고 저장하세요.

메일은 읽음 표시되지 않습니다(IMAP `BODY.PEEK` 사용). 보안 관련 내용은 아래 [보안](#보안)을 보세요.

## 동작 방식

```
다음 / 네이버 / Gmail / 기타 IMAP  (계정별로 동시에)
   │  N분마다 새 메일만 가져옴 (계정별 UID 기준, 첫 실행 시 최근 2일)
   ▼
업무 메일인가?  ── lib/rules.js
   │  · 제목/발신자에 제외 키워드 "(광고)", "뉴스레터" 등 → 무시
   │  · 회사 도메인 / 지정한 발신자 → 업무
   │  · 제목에 업무 키워드(회의, 마감, 요청, 검토 ...) → 업무
   │  · 본문에만 키워드가 있으면 날짜도 있을 때만 업무
   ▼
날짜·시간 추출  ── lib/dateExtract.js
   │  · 10월 2일(금), 2026. 10. 7., 9/30, 10.3(금)
   │  · 내일, 모레, 이번 주 금요일, 다음주 화요일, 차주 월
   │  · 오후 2시~4시, 14:00-15:30, 10시 반, 2pm  (시각이 다음 줄에 있어도 연결)
   │  · 금일·익일·명일·오늘·내일·모레는 시간이나 요청 표현("회신 부탁", "공유 바랍니다")이 있을 때만 일정으로
   │  · ASAP·긴급·급히·가능한 빨리·EOD·금일 중 → [긴급] 표시, 날짜가 없으면 받은 날 마감
   │  · "까지/마감/제출/부탁/요청" → 마감, "회의/미팅/세미나" → 회의 (회의는 기본 1시간)
   │  · 답장(RE:)의 인용된 이전 메일은 제외, 전달(FW:)은 포함
   ▼
위젯 "새 메일" 탭에 후보 표시 + 윈도우 알림
   │  제목/날짜/시간을 고치고 [캘린더에 추가] 또는 [무시]
   ▼
위젯 캘린더 (월 달력 + 다가오는 일정)
   · 📅 버튼: 해당 일정을 .ics로 열어 Outlook / 윈도우 캘린더에 바로 추가
   · "전체 일정 .ics로 내보내기": Google 캘린더 등에서 가져오기 가능
```

날짜를 못 찾은 업무 메일은 받은 날짜의 **할 일**로 제안됩니다(기본 체크 해제).
설정에서 "날짜가 있으면 확인 없이 바로 캘린더에 추가"를 켜면 후보 확인 단계를 건너뜁니다.

### 규칙의 한계

규칙 방식이라 문장 뜻은 이해하지 못합니다. 예를 들어 "10월 2일 회의는 취소되었습니다"도
일정으로 잡히고, "다음 달 초" 같은 모호한 표현은 인식하지 못합니다. 그래서 기본값은
**후보를 보여주고 사람이 확인**하는 방식입니다. 연도 없는 날짜는 메일 받은 해로 보되,
60일 넘게 과거가 되면 다음 해로 봅니다(12월 메일의 "1월 5일" → 다음 해). 시각에
오전/오후가 없으면 1~7시는 오후로 봅니다.

## 창 / 트레이

- 프레임 없는 위젯 창이며 제목 줄을 드래그해서 옮길 수 있습니다(위치 저장).
- `—` 버튼이나 창 닫기는 **숨기기**입니다. 시스템 트레이 아이콘 클릭으로 다시 열고,
  트레이 우클릭 메뉴에서 "지금 메일 확인", "항상 위에 표시", "윈도우 시작 시 자동 실행",
  "종료"를 고를 수 있습니다.

## 보안

**저장 데이터**
- 설정(계정)과 데이터(일정, 후보, 메일 요약)를 **파일 전체 암호화**해서 저장합니다. Windows DPAPI(Electron `safeStorage`)를 쓰기 때문에 같은 윈도우 사용자 계정에서만 풀 수 있습니다. 메일 비밀번호는 여기에 한 번 더 따로 암호화됩니다.
- 다른 PC나 계정에서 복사해 와서 풀 수 없는 파일은 덮어쓰지 않고 `*.unreadable-<시각>`으로 따로 보관합니다.
- 처리하지 않은 일정 후보(메일 요약 포함)는 30일이 지나면 자동으로 지웁니다.
- 📅 버튼용 `.ics` 임시 파일은 5분 뒤, 그리고 앱을 시작하거나 종료할 때 지웁니다.
- 설정 탭의 **모든 데이터 삭제**로 계정·비밀번호·후보·일정을 한 번에 지울 수 있습니다.

**메일 서버 연결**
- 항상 TLS 1.2 이상으로 접속하고, 서버 인증서를 검증합니다.
- 메일을 읽기만 하고, 보내거나 지우지 않습니다. 메일 서버 말고는 어떤 서버와도 통신하지 않습니다.

**앱 자체**
- 위젯 화면은 샌드박스에서 실행되고, Node 접근이 차단되어 있습니다(`contextIsolation`, `sandbox`).
- 엄격한 CSP를 적용하고, 메일 내용은 항상 텍스트로만 화면에 넣습니다. 그래서 메일에 스크립트를 넣어 보내도 실행되지 않습니다.
- 다른 페이지로 이동, 새 창, `<webview>`, 브라우저 권한 요청(카메라 등)을 모두 차단합니다.
- 메인 프로세스는 위젯 자신의 페이지에서 온 요청만 처리합니다.
- 배포용 빌드에서는 개발자 도구를 끄고, Electron fuses로 `RunAsNode`, `NODE_OPTIONS`, `--inspect`를 차단하며, `app.asar` 밖의 코드는 불러오지 않습니다.

**사용할 때 권장 사항**
- 메일 비밀번호 대신 **앱 비밀번호**를 쓰세요. 유출되더라도 그 비밀번호만 폐기하면 됩니다.
- 회사 메일을 개인 PC 도구로 가져와도 되는지 회사 보안 규정을 확인하세요.
- 설치 파일에 코드 서명이 없어서, 처음 실행할 때 Windows SmartScreen 경고가 뜰 수 있습니다.

## VS Code에서 실행

1. [Node.js](https://nodejs.org) 22 이상 설치 → 폴더 열기 → 터미널(`Ctrl+\``)에서 `npm install`
2. 왼쪽 **실행 및 디버그**(`Ctrl+Shift+D`)에서 **위젯 실행 (Electron)** 을 고르고 `F5`
   - 메인 프로세스(`main.js`, `lib/`)에 중단점을 걸 수 있고, 로그는 디버그 콘솔에 나옵니다.
   - 위젯 화면 쪽은 위젯을 클릭한 뒤 `F12`(또는 `Ctrl+Shift+I`)로 개발자 도구를 엽니다.
3. **규칙 테스트 (npm test)** 로 날짜 추출/업무 메일 규칙 테스트를 돌릴 수 있습니다.

## 테스트

```bash
npm test
```

규칙 엔진(`lib/`)은 Electron 없이 Node만으로 테스트됩니다.

## Windows 설치 파일 빌드

```bash
npm run build:win
```

또는 GitHub Actions의 `Build Windows Installer` 워크플로를 수동 실행하면 Actions
아티팩트로 `.exe`가 올라오고, `v1.0.0` 형식의 태그를 푸시하면 GitHub Release에도 첨부됩니다.

```bash
git tag v1.0.0
git push origin v1.0.0
```

## 파일 구조

| 파일 | 역할 |
| --- | --- |
| `main.js` | 창/트레이, 주기적 메일 확인, 설정·일정 저장, IPC |
| `preload.js` | 렌더러에 `widgetAPI` 노출 |
| `lib/mailWatcher.js` | IMAP 접속(imapflow) + 메일 파싱(mailparser, EUC-KR 포함) |
| `lib/providers.js` | 다음/네이버/Gmail IMAP 서버 설정과 안내 문구 |
| `lib/rules.js` | 업무 메일 판별, 제목 정리, 인용문 제거 |
| `lib/dateExtract.js` | 한국어 날짜/시간 추출 |
| `lib/processMail.js` | 메일 1통 → 일정 후보 |
| `lib/ics.js` | iCalendar(.ics) 생성 |
| `src/` | 위젯 UI (새 메일 / 캘린더 / 설정 탭) |
